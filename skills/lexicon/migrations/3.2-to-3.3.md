# Schema 3.2 to 3.3

Schema 3.3 restricts Flow participants to Architecture elements and adds optional caller, callee, and call-site code references on each step. Domain relationships remain valid outside Flows. Source targets remain owned evidence mappings.

Read the original XML and inspect each Flow's referenced relationships. When every endpoint is already a Person, Software System, Container, or Component, preserve the steps and change the root to `schema="3.3"`. Code detail is optional; do not invent references during migration.

For a step with a Context or Concept endpoint, inspect the interaction and its implementation. Find the existing Architecture responsibility that performs the action. Preserve the original domain relationship and author or reuse an Architecture interaction relationship; update the step's relationship while retaining the Flow and step IDs, order, labels, and meaning. An internal action may use a self-relationship on a Component. Add a missing responsibility only when the inspected source or specification supports it. Never mechanically turn Concepts into Components, discard steps, or treat source files as participants. If responsibility or ordering is ambiguous, discuss it before changing the model.

Optional XML attributes `caller`, `callee`, and `call-site` reference explicit IDs of code links owned by the same Flow. JSON uses `caller`, `callee`, and `callSite`. Each referenced link must have `kind="code"` and a symbol or positive line target. Existing links can be reused after inspection; retain their IDs. Caller belongs to the relationship's source participant; callee belongs to its destination. A call-site link locates the connecting operation. Describe HTTP, events, and other transport mechanisms in the step label and relationship instead of suggesting a direct call. Leave unavailable sides unspecified, including a human caller or an external implementation.

These associations require source review; validation checks Architecture endpoint types and link references, not responsibility ownership or execution order. Follow README.md for backup, current-schema/source validation, exact-byte undo, and preservation of canvas.json, assets, conversations, source files, and unrelated model content.
