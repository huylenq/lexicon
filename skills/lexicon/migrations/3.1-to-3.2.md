# Schema 3.1 to 3.2

Schema 3.2 makes SourceLink a union of CodeLink and DocumentLink. Both remain stored as `<code-link>` / `codeLinks`; every link now requires `kind="code"` or `kind="document"`. This version boundary prevents older viewers from discarding kind or dispatching to the wrong reader.

Read the original model and linked sources. For existing 3.1 behavior, Markdown file/line/heading links become `document`; implementation files and symbol links become `code`. Inspect ambiguous text files and their explanations before choosing a kind. A `.md` link with `symbol` previously had unsupported symbol lookup: preserve it as `code` unless the user authorizes replacing the locator with an inspected document heading. Never infer kind from an enforcement or specification role alone.

Change the root to `schema="3.2"` and add the reviewed kind to each link. Preserve owner IDs, explicit link IDs, paths, symbols, headings, lines, roles, descriptions, and model meaning. Code links reject heading; document links reject symbol and support either heading or line. A heading requires Markdown. Do not discard conflicting selectors to make validation pass; inspect and resolve the intended target.

Existing code targets and Markdown heading targets retain their IDs. Document file/line targets now use document-file/document-line locator tags so code and documents can independently address the same path. The viewer remaps unambiguous legacy target and mapping references in canvas snapshots, retaining positions, notes, and bindings. Existing explicit link IDs survive this change. Where an old target becomes ambiguous because both kinds now use the same location, retain the original evidence kind while migrating; add the other kind only after opening the migrated canvas. Old URLs carrying an explicit mapping ID remain disambiguated.

Follow README.md for backup, current-schema/source validation, exact-byte undo, and preservation of canvas.json, assets, conversations, and source files. Do not regenerate the model or downgrade the schema.
