# Schema 2.0 to 3.0

Schema 3.0 retains Context, Concept, Relationship, annotations, and code-link XML. The only required XML change for a valid domain-only model is the root `schema="3.0"`. Preserve its contents and stable IDs; no architecture or flow is required.

The in-memory / embedded patch field for concept ownership is now `parent` instead of `context`. XML still nests each concept inside its owning context, so existing XML needs no ownership rewrite. Code-link IDs remain optional; do not add or replace IDs as a side effect of migration.

The current contract also admits root Person and Software System elements, nested Container and Component elements, and root Flow elements containing ordered Step records. These are optional authoring capabilities. Do not add them while migrating unless separately requested. Ordinary relationships may connect any structural elements.

Read the document, preserve meaning, validate the schema-3 result, and report the version change. Use the common preservation and delivery instructions in README.md.
