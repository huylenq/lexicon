# Lexicon reader

Projects open in [Canvas](CANVAS.md), with model references, notes, drawings, and media. Run `bun run dev:canvas` for an isolated checkout workshop.

A local reader for domain meaning, C4 software structure, and ordered flows, sharing relationships, annotations, and source links. Read the explanation, explore its connections, and inspect the implementation.

```sh
bun install --frozen-lockfile
bun run build:client
bun start
```

Open http://127.0.0.1:5374. Development uses `mise run viewer` from the repository root, with Vite on http://127.0.0.1:5373.

For a self-contained macOS application, see the [desktop installation and release guide](desktop/README.md). The desktop app includes Bun and offers clickable update notices.

The production build is installable as a PWA. Open port 5374 and use **Install app** when offered, or the browser's install menu. Supporting desktop browsers can place the inline header alongside native window controls through Window Controls Overlay. Other browsers retain their standard app title bar. The header's empty space drags the window; its links and buttons remain clickable.

Keep `bun start` running to read projects and source. The service worker caches only the built app shell, including the canvas assets. If the server is unavailable, the app opens with a reconnect message; model data, source code, and library changes are never cached. Updates activate after all existing app windows and tabs close. PWA caching is enabled only in production builds, so Vite development stays live.

The library includes a self-contained Shop example plus your registered projects. Add a project by its absolute folder path. Removal affects its library registration only.

- **Read:** a vertical stack of context, concept, relationship, and mapping explanations overlays the right side of Canvas. Left click opens or replaces a single **Preview** card. Middle click or Command-click (Ctrl-click on Windows/Linux) opens a **Pinned** card at the end of the stack; pinning the current Preview keeps it in place. Clicking the Preview label also keeps it. Opening or returning to a Pinned card dismisses any other Preview. Reopening an existing card reveals it without duplicates. Close removes only that card. Resize the overlay at its left edge, or press `w` or use the Reader toggle in the App header to hide it without clearing your cards.
- **Relationships:** select either endpoint to open that context or concept, or select the relationship name to read its explanation. Each is a separate link that also supports opening in a new tab.
- **Source Reader:** an independently toggled, resizable pane for implementation code and supporting documents. Source links from Browse and Canvas open this same pane. Model navigation preserves the current source location; closing and reopening Source Reader restores its reading position and view. It has its own previous/next location controls, code declaration focus, and document heading navigation. On narrow screens, Source Reader fills the workspace and **Back to reader** returns to the explanation.
- **Find:** search names, descriptions, annotations, files, and symbols. `/` focuses search; Escape closes code or navigation.
- **History:** the URL shares the active object and source selection. Browser Back/Forward restores the whole reader stack, including its Preview, Pinned cards, and closed cards. Stack contents, visibility, and scroll position are remembered in this browser per project. Copy link on a card shares that card.
- **Refresh:** reread the model from disk. Parsing is uncached.

The light and dark themes use neutral surfaces, a vivid pink interaction accent, and the system UI font. Dark mode uses near-black backgrounds. Navigation, toolbars, and metadata use compact spacing; explanations retain a comfortable reading measure. Object names remain neutral, with semantic color confined to their leading icons across Browse, Read, Canvas, and Code. Context icons are neutral. Entity, value (including value object), aggregate, service, and event have stable icon colors; other classifications use the generic concept icon and color. Hovering an icon or focusing its containing control reveals its type and authored classification. The sidebar uses a flat selection tint matching the object icon, including neutral gray for Contexts, without an indentation guide or vertical selection bar. Code syntax has its own theme colors.

Browse visibility sits beside the project identity; Reader and Code have their own pane controls; Agent opens from the bottom status bar. Browse is a floating navigation shelf inset 12px from the left edge and vertically centered below the header, with content-fit height and a scrolling list beneath its search field. Its height leaves clearance for the bottom-left zoom and fit controls, including when the window or canvas pane is resized. Searching keeps the shelf at its pre-search height so the input stays in place; clearing search restores content-fit sizing. Toggle it from the header. Code and Chat have local close buttons; optional panes restore their state when reopened. Back and Forward in the application header follow browser history; Code retains its independent source history.

The [icon catalogue](client/public/icons.svg) contains 31 original SVG symbols for model objects, classifications, annotations, and viewer controls. Each uses a 20-unit grid, 1.5-unit rounded strokes, and inherited text color. The catalogue is also the production sprite; `Icon.tsx` provides typed names and hides decorative SVGs from assistive technology while adjacent text or button labels carry their meaning.

Reader cards have separate rounded surfaces and visible gaps, and share one scrollbar. Earlier titles collect at the top as you scroll, with the title area capped at roughly one-quarter of the reader height. Clicking a title reveals its card. Opening or clicking a card makes it active for Agent context and canvas synchronization; scrolling alone leaves the active card unchanged. Clicking empty canvas preserves the stack. On narrow screens, Reader fills the workspace and switching back to Canvas preserves its cards.

## Canvas

Canvas extends beneath the resizable reader overlay for every project. Model objects keep their Lexicon icons and relationships; freeform notes, drawings, and media add working context. Select an object or relationship to read it. On narrow screens, the header’s **Reader** toggle returns to the same canvas view.

The **2D / Planes** switch chooses the canvas view. 2D offers Domain, Architecture, Combined, and Linked Sources; Planes shows Domain, Architecture, and Linked Sources on separate planes. All 2D views share one editor and a **2D skin** toggle group: Standard cards and connections, Atlas Ink, or Atlas Village. Atlas renders contexts, systems, and containers as territories, concepts and components as landmarks, people as travelers, and relationships as paths, updating as objects move. Skins share positions and selection. Select an object in Atlas to edit its landmark, terrain, or path appearance. The skin is remembered in this browser. See [Atlas skins](CANVAS.md#atlas-skins) for the defaults and scope.

Linked Sources uses tldraw file cards and precise code/document targets derived only from the model’s source links, with cross-dimension radials connecting them to their owners on Domain and Architecture. It opens without a file scan or separate source index, and retains potentially stale references. Combined composes Domain, Architecture, and Linked Sources from their saved pages, with one canonical copy of each linked target. Authored source links connect owners to those targets directly. Each plane has the same movement handle and drawing ownership controls. **Lexicon settings → Development → Files / File Map** enables the experimental filesystem view in this browser (off by default). Its **Browse Files** button opens the LOC-weighted filesystem map outside the planes; **Back to canvas** returns to the previous presentation. Browser history and reload preserve this navigation. Files uses a standalone Canvas 2D renderer and never mounts or writes a tldraw document. Existing File Map annotation records are preserved but not displayed. The following inventory rules apply to Files browsing: The project-root `lexicon/` artifact directory is always omitted, including tracked files. Git projects otherwise include tracked and non-ignored untracked files; non-Git projects also honor nested `.gitignore` rules and negations, and omit dependency and build directories. Ignored files are excluded before LOC measurement and are not added back by source links; declared evidence remains accessible in the Reader. Embedded Git repositories and initialized submodules are traversed. Their own ignore rules and ancestor ignore rules both apply; project globs use paths relative to the selected source root. Refresh files rescans the checkout. The inventory is capped at 100,000 files and reports partial results explicitly. File tiles are drawn in one Canvas 2D background with viewport culling and zoom-dependent directory aggregation, rather than one tldraw shape per file. Linked Sources and Combined use the same gestures, tools, and skin controls as Domain and Architecture.

Tile area uses physical LOC, including blank lines and comments, summed for directories and adjusted for frame padding. The root frame is unlabeled, folders have tinted backgrounds and names without icons or counters, and file labels are centered. Empty, binary, oversized, and unmeasured files use minimum-weight tiles; hover explains their measurement. The server caches counts for unchanged files and scans with eight readers, a 16 MiB per-file limit, a 256 MiB read budget, and a ten-second deadline. Refresh retries deferred counts. File Map uses locally bundled [Material Icon Theme](https://github.com/material-extensions/vscode-material-icon-theme) icons for common languages, documents, and configuration files, plus a generic fallback. The same file icons appear in file search. Icons are decoded once per type and drawn into the map bitmap. Their MIT license ships at `/licenses/material-icon-theme.txt`.

Click a file to open it in Source Reader, including files without model mappings. Markdown opens in the document reader; binary files and files over 2 MB report a reading error. Find a file by path in Search files, then click a result or press Enter. Double-click a directory to focus it. With the map focused, arrow keys move among siblings and parents/children, Enter opens a file or focuses a directory, Space collapses a directory, and Home returns the keyboard cursor to the root. Selection and search preserve map geometry. The experimental File Map supports browsing, pan, and pointer-centered wheel zoom; drawing tools are confined to the model canvas. Inventory changes can reflow the map.

In Planes, selecting a model item highlights its linked source footprint; selecting a file exposes its authored mappings back to model items. Source links are grouped by owner and target, with at most 120 groups drawn, prioritizing the selected target or owner. The Linked Sources plane fits its linked targets independently. All planes share pan, scene zoom, tilt, and separation. Click a plane label to open its 2D view.

The 2D drawing tray docks in the center of the canvas toolbar when there is enough room between the view controls and actions. On smaller workspaces it returns to the bottom, centered in the area left of the Reader overlay. It uses tldraw's standard tools and overflow menu in both positions.

Standard context frames and Atlas territories automatically encompass their inner nodes and labels as they move. Select a context in Atlas for **Edit border** to sculpt its coastline. Border edits are preferences: a bay yields to a node and returns when space allows. **Reshape to contents** clears those preferences. Switching skins keeps objects in place.

The toolbar uses the shared icons for **Fit model**, **Locate**, and **Arrange**. Right-click a model object for **Focus**. Hover a model object or relationship to navigate to its declared sources through cross-dimension radials; hover a source target or file card to navigate back to its owners. **Back to overview** restores the camera from before Focus. **Add note** attaches a note to the selection. **Notes** searches canvas text; **Selection actions** opens attachment, model-edit, and selection-export controls. Routine save status sits beside the legend in the footer. Recovery and conflict messages appear when needed.

Canvas saves placements and freeform content to the project, while camera and visibility remain personal. On first open, compatible earlier placements and camera migrate from this browser. Existing saved canvases and recovery drafts take precedence. See [Project canvas](CANVAS.md) for files, recovery, and model-edit behavior.

Code references share a target for identical declared file/symbol or file/line links while preserving each mapping's role and explanation. A code card opens the Code workspace without replacing the reader; a code connector opens its explanation in the reader and source in Code. Targets use declared paths and symbols, without resolving aliases.

Old `?canvas=graph` and `?canvas=tldraw` links open the same tldraw canvas and normalize to an ordinary project URL, preserving the selected item and code location.

Earlier XML models open a preserved-document mismatch screen with Agent available for explicit migration. See [MIGRATION.md](../MIGRATION.md). The model format is in [MODEL.md](../MODEL.md).

## Agents

An agent represents one task and conversation. Select its canvas pill to see its perspective, then choose **Conversation** to continue the discussion; use **+** in the agent HUD to start another task. Naming is optional: the first request becomes the task name. Moving between concepts, relationships, and source files preserves the discussion. Each sent message keeps its selected context and source links.

Choose **Start agent here** from a model item or canvas selection, or start an empty task from **+**. Working context can include concepts, architecture elements, relationships, and flows together; edit it with **Context** beside the selected agent. Add the canvas selection or choose references by name. Context is independent of reader navigation and canvas placement. Drag the agent pill to give the task a convenient place in the canvas.

In **Model only**, requested edits build an unsaved **Model draft** on the canvas. Additions are temporary objects, relationships connect their explicit endpoints, and removals leave the saved objects intact. Select a change marker to inspect the saved and draft values beside the object without opening chat or moving the camera. Follow-up requests refine the same draft. **Approve changes** saves the whole reviewed delta; **Discard draft** removes it without changing model.xml. Both actions wait until the agent stops. Approval is recoverable: if the exact reviewed model was saved but finalization failed, retry completes that approval without writing again. A changed saved model makes the draft stale and blocks approval; discard it and ask the agent to prepare a new draft against the current model. Project metadata, flows, and migrations remain reviewable even without a corresponding canvas shape.

Context outlines and a subtle focus pointer show the selected agent's perspective. Temporary marks and preview objects never save canvas placements or model content. Changes elsewhere remain accessible from the agent's controls, including flows without canvas shapes. **Conversation** opens the same task's transcript and composer; minimizing it returns to canvas inspection. Navigation only happens through an explicit locate action. The agent HUD and named edge indicators help locate off-screen tasks. The resize handles on the conversation pane's sides and lower corner retain separate canvas and expanded sizes for each agent in this browser.

**Task details** (⋯) holds connection and checkout information, Open in T3 Code, settlement, and archive/discard actions. **Working** indicates runtime activity; **Review draft** points to an unsaved model candidate. Minimize, expand, and switching tasks preserve the composer and running work. `⌘\` (`Ctrl+\`) toggles the current session; **Enter** sends and **Shift+Enter** adds a line. Settled and archived tasks remain in task history under **+**. Pending drafts keep a **Review draft** entry so you can approve or discard them without resuming the conversation.

All sessions run through T3 Code. Start T3 on the same machine, open **Lexicon settings → Connections** from the library or project header, and enter its local server address and a fresh pairing token. Generate the token with `t3 pair --label Lexicon` (or `node apps/server/src/bin.ts pair --label Lexicon` from the T3 checkout). For a separate data directory, supply `--base-dir`. Lexicon stores the resulting credential in its local registry and never sends it to the browser. This pairing belongs to the Lexicon server profile and applies to every project and task, including other open browser tabs. Existing tasks remain bound to their original T3 environment and checkout. Disconnect removes the local credential for all projects without stopping or deleting T3 tasks; revoke the connection in T3 to invalidate it there too.

New tasks start in **Model only**, the groomer mode. It uses Codex through T3's explicit read-only execution mode: ordinary reads run without approval prompts, while source writes and approval escalation remain blocked. It can inspect source, explain the system, navigate the viewer, and prepare validated model drafts. Only Codex models are offered in this mode. Choose **Code + model** for ordinary coding-agent execution in T3's editable workspace mode, with providers supported by its MCP gateway. The conversation and T3 thread stay the same. Stop the current turn and approve or discard any pending model draft before changing scope. Examples remain read-only.

Ask questions to discuss the model; request edits to prepare refinements. Model-only edit, patch, and migration tools update the task's draft, and its subsequent inspection/search sees that candidate. Tool receipts clearly distinguish unsaved draft updates from saved writes. Only approval in the viewer saves a model-only draft, rechecking its identity, the saved revision, and source links. Code + model edits save directly through the same validated MCP boundary without a model approval workflow. Reply code fences do not execute. Embedded agents have no model-undo action; checkpoint restore is available in T3 Code through **Open in T3 Code**. Code-capable agents are instructed to use MCP for model edits; their workspace access does not independently exclude model.xml from filesystem writes.

The T3 server must advertise the current gateway approval policy and read-only execution support; older builds are rejected before a task starts. Rebuild and restart T3 to load those capabilities. Lexicon tools run through T3's existing agent connection, with access granted separately for each turn. Follow-up messages keep the provider session without restarting it to refresh Lexicon access. Execution activity, approvals, and questions appear in the conversation. **Stop** interrupts the active turn. **Review changes** appears when the session has code changes through its latest completed checkpoint; file buttons open Source Reader. A follow-up without edits preserves earlier changes, while reverting them removes the review. Later changes may still be running. The displayed branch and path identify the selected checkout. Automatic worktree creation and remote T3 hosts are not supported; existing linked worktrees can be opened as projects.

An unmodeled project needs no initialization before a question. Schema mismatches preserve the file and allow explanation or an explicitly requested migration draft. Only schema 3.3 is parsed. T3 owns thread history; Lexicon retains project bindings, context, operation receipts, and pending model drafts. Drafts survive completion, Stop, and reload for later review; already saved coding-agent changes remain applied. Minimize hides a widget. Settled and Archived tasks leave active work and remain in task history, where Resume or Restore preserves the conversation and task data. **Discard task** removes an unsent local task; **Discard draft** clears only its unsaved model candidate. Closing the final task leaves an empty workspace; New agent creates a separate task.

**Open in T3 Code** opens this task in the desktop app without starting a turn. The server verifies its checkout and sends the bound environment and thread IDs through T3's local desktop-control socket, then waits for acknowledgement. This uses the same protocol as Rooms. On macOS the defaults are `~/src/t3code/apps/desktop/.electron-runtime/T3 Code (Dev).app` and `~/.t3/dev`; override them with `LEXICON_T3_APP_PATH` and `LEXICON_T3_STATE_DIR`. The desktop app must know the paired T3 environment. A failed activation is reported in the conversation.

Only agents belonging to the selected Lexicon project are exposed. Their T3 bindings must match the exact source checkout and paired environment. The adapter reads T3's server-wide project list to resolve those bindings; the pairing credential is not project-limited. Agents read project source filters from the artifact root's settings file and apply Git-ignore rules to discovery. These instructions do not restrict the runtime's filesystem access.

Messages keep your original text in both Lexicon and T3. Lexicon supplies a short, separate execution brief with editing scope and working-item references. The agent reads model content through MCP as needed, rather than receiving a model dump with every message.

The UI uses Lexicon components. `server/agents/` uses T3's typed RPC client, thread reducer, and pending-request logic. Source packages and the required Effect patch are pinned in `vendor/t3/revision.json`; `bun install --frozen-lockfile` needs no sibling checkout. To update the dependency, run `python3 scripts/package-t3.py /path/to/t3code <commit>`, align Effect if its version changed, and run `bun install` and the agent checks. For an uncommitted local integration, add `--working-tree`; its distinct package version records the base commit, source fingerprint, and scoped patch so the snapshot remains reproducible. Versioned archive paths prevent stale package-cache reuse. The packaging script leaves T3's checkout untouched.

Before releasing a new integration pin, run `bun run test:agent:live --t3-bin /absolute/path/to/t3` with an authenticated Codex provider installed. A JavaScript T3 server entrypoint is also accepted; `--model` optionally selects an advertised model. This check starts separate T3 and Lexicon servers on temporary ports, pairs only those instances, and exercises a real Model-only MCP draft, approval and retry, then an ordinary coding turn in a temporary Git project. It uses the installed provider's authentication and removes its servers and temporary state afterward. It never pairs with the running user environment. Unit and isolated browser checks run on pull requests and gate desktop releases; the live provider check runs separately because it requires local authentication.

## Checks

```sh
bun run test
bun run typecheck
bun run build:client
bunx playwright install chromium
bun run test:browser
bun run test:canvas
bun run check ../examples/shop --code-root ../examples/shop
```

The API binds to `127.0.0.1`. `LEXICON_VIEWER_API_PORT` changes port 5374. `LEXICON_VIEWER_DB` chooses a separate SQLite registry for tests; the default preserves `lexicon-viewer.db`. API source requests identify a declared file/symbol or file/line target independently of its domain mappings; earlier owner/index requests remain supported. The server accepts only targets declared in the model and confines the resolved file to the code root.

Browser checks build and serve the client on port 5384 with a separate in-memory registry. Reader, source-navigation, and conversation checks use the tldraw canvas. `bun run test:canvas` exercises Canvas through `bun run start` on port 5395 with temporary projects and its own in-memory registry. To use an installed Chrome instead of Playwright's Chromium, run `PLAYWRIGHT_CHANNEL=chrome bun run test:browser`.

For reader frame-time measurements, build the client, start an isolated server with `LEXICON_VIEWER_API_PORT=5388 LEXICON_VIEWER_DB=:memory: bun run start`, then run `bun scripts/reader-performance.ts http://localhost:5388` in another terminal. The script scrolls 5-card and full Shop stacks down and back three times in Chromium at 1600×900 with 4× CPU throttling. It reports animation-frame intervals and CDP script/layout/task time; these are comparative measurements, not portable performance thresholds. Keep other builds and tests idle during comparison runs. Stop the isolated server afterward.

For a detailed Canvas trace, build with `bun run build:client --sourcemap`, use the isolated server above, and run `bun scripts/reader-trace.ts http://localhost:5388 /tmp/reader-canvas /absolute/path/to/lexicon/model.xml`. The optional model is copied to a temporary project; the original is untouched. The script exercises both morph directions, tile-row changes, settling, and distant navigation with up to 24 concept cards. It writes a Chrome `.trace.json`, `.cpuprofile`, screenshot, and summary beside the output prefix. Import the trace in Chrome DevTools Performance. Tracing adds overhead, and nested event durations must not be added together as total runtime.

## Planes presentation

Choose **Planes** in the canvas toolbar to explore Domain, Architecture, and Linked Sources on separate planes. The reader, navigation, Source Reader, and Agent stay in place when changing canvas presentations. Relationships explain correspondence between dimensions; source links open source evidence. Hovering or selecting a connector marks both endpoints.

Planes saves its Domain, Architecture, and Linked Sources pages in `lexicon/canvas.json`, alongside existing pages, notes, and media. Undo and Redo span the planes; Refresh model updates their semantic references in place. The ordinary canvas remains the default. See [Planes promotion](../PLANES.md) for validation and remaining interaction work, or run `bun run dev:planes` for an isolated Shop development session.

File Map detail shares file icons, locator labels, and target identities with Linked Sources. Planes renders source connections directly between owners and target objects. Small files use an anchored detail card; file search also finds declared symbols and document headings. Detail changes neither LOC area nor model XML.

### Personal settings

**Lexicon settings** is available in the library, every project header, and agent connection status. Connections are saved in this Lexicon server’s registry database (the desktop profile uses its user data directory; development uses `LEXICON_VIEWER_DB` or the viewer database). Pairing and disconnecting update open tasks through shared settings events. Authentication cookies remain server-side, and pairing tokens are cleared after use.

Appearance and Development settings are browser-local preferences. Theme and the experimental Files / File Map switch apply across projects in that browser. They are independent of project read-only status. Source filters remain shared project configuration below.

### Project file settings

Open **Project settings** in the project header to edit source include/exclude globs. Settings are shared in the resolved artifact root's `lexicon/settings.json`. Patterns are relative to the source checkout; empty includes select all files, any include may match, and exclusions win. Default exclusions are `**/*.lock` and `**/.*/**` for lock files and dot-prefixed directories at any depth; remove either pattern to include those files. Git ignore rules apply as well, including to tracked files. Saving refreshes Files browsing without changing model XML or existing evidence links.

The Lexicon skill uses the same inventory through `bun skills/lexicon/scripts/lexicon.ts files <artifact-root> --code-root <source-root>` from the bundle root. Invalid settings stop discovery and report an error. In Project settings, use **Load default filters** to prepare a replacement, then edit and save it; Cancel leaves the original file untouched. The skill’s `files` command lists paths without computing LOC metrics. See [project settings](../MODEL.md#project-settings) for the file format.

### Source naming and compatibility

The client uses `SourceReader`, the shared `CanvasPane` for every 2D plane and Combined, and the experimental `FilesPane`/`FileMap`; shared filesystem data is `FileInventory`. The Files API is `/api/projects/:id/files` with `/files/file` for content. Earlier `/repository` endpoints and `repository=1` browsing URLs remain accepted. Serialized `repository:` file selections, `source` dimension keys, canvas page IDs, and `code`/`codePane` URL fields retain their identities so saved links, layouts, and recovery data continue to work. The semantic model still uses `SourceLink` with the schema's existing `codeLinks` and `<code-link>` compatibility names.

### Flow code detail

Flows use Architecture participants. Open a Flow and enable **Show code** to expand its caller and callee targets into lifelines under their responsible participant. Select a symbol or call site to open Source Reader without replacing the Flow. Code detail preserves the step order and transport labels. Internal interactions can expand into several code lifelines within one Component. Unspecified code remains labeled; unavailable targets report the ordinary source-reading error. See [Flow authoring](../skills/lexicon/flows.md) and [schema 3.3 migration](../skills/lexicon/migrations/3.2-to-3.3.md).

Selecting a Flow opens its sequence in a resizable horizontal glass overlay at the bottom of the canvas, sharing Browse’s container styling without shrinking the canvas or Source Reader. Drag the sequence header left or right to reposition it within the workspace. Its width fits the diagram up to the available workspace width, then scrolls horizontally. Its height fits the content up to a resizable maximum (48% of the workspace by default), then scrolls. The Reader card keeps its description, annotations, and source links. Inspecting participants, messages, or code keeps the sequence available; navigating to another item hides it. Single-click inspects; double-click locates the participant, relationship, or code target on the canvas. Locate switches individual planes when needed and preserves Combined or Planes presentations.
