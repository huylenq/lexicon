# Project canvas

The model canvas uses tldraw, with **2D / Planes** views in its toolbar. Domain, Architecture, Linked Sources, and Combined share the same 2D editor, tools, gestures, skins, and save lifecycle. Earlier `?canvas=graph` and `?canvas=tldraw` links open this same canvas and normalize to an ordinary project URL. Browse, Read, Source Reader, and Chat remain independent panes.

For the normal local viewer, run `bun run build:client` followed by `bun run start` from `viewer/`, then open port 5374.

For an isolated development workshop:

```sh
cd viewer
bun install --frozen-lockfile
bun run dev:canvas
```

Open [the checkout workshop](http://127.0.0.1:5393/p/canvas-workshop). It includes source for all five code links. This command uses client port 5393, API port 5394, and a separate `lexicon-canvas-prototype.db` registry. Override them with `LEXICON_CANVAS_PORT`, `LEXICON_VIEWER_API_PORT`, and `LEXICON_VIEWER_DB`. Restart the command after server changes; the client reloads through Vite.

## Files and recovery

| Content | Storage |
| --- | --- |
| Contexts, concepts, relationships, code links, formal annotations | `lexicon/model.xml` |
| Shared placements, map appearance, notes, drawings, reference copies, attachments | `lexicon/canvas.json` |
| Images and video | `lexicon/assets/<content hash>.<extension>` |
| Camera, selection, search, pane preferences | This browser |
| Unsaved canvas recovery | This browser's IndexedDB, per tab and artifact root |

Opening an unmodeled project leaves its files untouched until the first canvas edit. Canvas autosave writes a versioned companion file in the resolved artifact root. Linked code worktrees use the same artifact-root resolution as the model. Commit `canvas.json` and its assets together to share them or move the project. Generated relationship routes and hidden-state flags are normalized before saving, so camera and presentation changes do not rewrite the shared document. Shape labels are cached for export and missing references; the current model supplies their meaning.

A save checks the file's content revision, acquires an exclusive local file lock, writes and flushes a temporary file, and renames it into place. `.canvas.previous.json` retains the preceding valid version. An abandoned save lock can recover after its owning process exits. A corrupt or newer-format canvas is preserved and blocks autosave. **Recover previous canvas** restores a validated backup and archives the replaced bytes as `.canvas-recovered-<time>.json`.

Failed saves remain visibly unsaved. Restart the local server to reopen a project after it stops. The browser records recovery drafts, restores this tab's pending edits after reload, and offers drafts from other tabs. Automatic recovery snapshots and project saves wait until an active drag ends, including when the pointer pauses or starts again while storage requests are pending; explicit saves, view switches, and closing still capture the current document. Keep the tab open or export if both the project save and browser recovery fail. Closing without waiting for the save indicator can lose edits that have not reached either storage system. This is local recovery, not a backup service.

Two tabs combine independent record changes using a three-way merge. Edits to the same shape or incompatible attachments require **Review versions**. The review shows the project content and offers a portable export, loading the project version, or replacing the reviewed revision with the current canvas. Loading another version archives the local draft. A newer intervening save is checked again. This is file reconciliation, not multiplayer presence or real-time collaboration.

## Use the canvas

During node dragging, only incident connections adjust their endpoint segments, keeping orthogonal paths and the existing attachment ports. Unrelated connections stay fixed, including when the pointer pauses. Projected connection previews are batched once per animation frame and visit only dirty nodes’ incident edges, dependent source links, and edges attached to every enclosing derived frame; release flushes the latest positions before full routing. After release, a background worker routes around moved obstacles and places labels; outdated results are discarded. A current result deferred by another gesture is retried when that gesture ends. This applies to Standard, source links, and both Atlas skins. Preview paths may temporarily cross obstacles. Changed routes animate only after release; Arrange and model projection request fresh routing.

**Linked Sources** renders only authored source-link targets, as compact rows in file cards, nested inside directory groups. Directory bounds follow their files and nested directories as they move, including negative local positions; undo restores the fitted bounds. Single-child directory chains share a path label (for example, `src/runtime/chat`). The hierarchy uses the same path-tree builder as Files, restricted to linked paths; all precise targets stay visible. Symbol glyphs distinguish classes, functions, methods, interfaces, type aliases, enums, and variables using source-derived metadata; unresolved or unsupported symbols keep a generic glyph. Whole-file links connect to the file card itself, without an inner row. Existing whole-file references transfer their notes and arrow attachments to that card. It does not scan the filesystem or require a separate source index. Potentially stale links remain visible. Its saved page and drawing identities are shared between 2D and Planes.

**Combined** composes Domain, Architecture, and Linked Sources from their saved pages. Source connections link owners to the canonical Linked Sources targets using the same orthogonal routing, rounded corners, and obstacle avoidance as semantic relationships. Source links retain dashed styling; relationship-owned links depart from the relationship label. Drag a plane heading to move that plane; select its heading to make it the destination for new drawings. Drawing edits and model-item rearrangements write back to the owning page. Moving an item in Combined therefore updates its individual plane layout too. Arrange lays out each plane independently, preserving plane offsets and freeform content. Atlas landmark, terrain, and path choices also write back to the owning page; paths that exist only in Combined retain their styles there. Existing Combined layouts gain a separate Linked Sources region without resetting the other planes' offsets.

The active drawing plane has a highlighted border and a badge beside the drawing tools. New drawings use that plane's coordinates; existing drawings and attachments retain their ownership when the active plane changes. **Separate dimensions** restores the spacing between planes. Hiding cross-dimension relationships replaces those connections with radial navigation without changing the model or saved node placements.

**Files / File Map** is a separate experimental filesystem view, disabled by default under **Project settings → Development options**. It uses a standalone Canvas 2D renderer and preserves project filtering. Its former annotation records remain stored but are not shown by this renderer. Enable the option to expose **Browse Files**; **Back to canvas** returns to the previous model view.

Open **Edge appearance** in the canvas toolbar to adjust diagram edges. Drag the **Corner radius** preview to round bends (0–256 px); short segments and nearby labels limit the rounding automatically. **Crossing hops**, on by default, adds small upward bridges on horizontal runs and gaps in the vertical lines underneath. Rounded corners and legacy curved reference copies also bridge crossings: the existing curve stays in place while the other edge gets a tight gap at the actual intersection. Two curves use stable edge identity to choose which passes over. Junctions, tangencies, labels, and tightly packed crossings are excluded. Rotated reference copies and Atlas roads keep their existing drawing. Both controls are browser preferences; they do not edit `canvas.json` or model XML.

Rendering, selection, and hit testing share the crossing geometry. Selection export calculates crossings among the exported edges, so omitted edges leave no gaps. Atlas's hidden Standard routes do not participate in on-screen crossings. Hops are skipped when their raised arc would crowd another route. During dragging, crossed routes update directly. After release, centerlines animate together and crossing bridges and gaps are recalculated from the displayed positions on each frame. Intermediate diagonal segments retain visible underpasses through bends; settled orthogonal routes retain raised hops. A spatial index limits crossing and label comparisons to nearby geometry. Each page caches its drawings across pan, zoom, and selection; route or label changes rebuild the indexed scene once, retaining unchanged drawing objects. `bun scripts/edge-hops-performance.ts` measures scene rebuilds and cached reads; `tests/canvas-edge-hops.e2e.ts` also records browser frame intervals while dragging in a 300-edge canvas. Timings depend on the machine and diagram density.

Select a model object and click **Add note** to attach a note. It follows the object and its context. The native **Note**, **Text**, **Draw**, **Arrow**, **Media**, and other tldraw tools create freeform content. Semantic relationships and code mappings use custom relationship shapes; native arrows do not create model relationships.

Labels and card bodies use the same native selection and dragging gestures. Right-drag or middle-drag pans; mouse wheel zooms. Shift-click or Command/Ctrl-click toggles a shape; Shift-drag adds a marquee selection. A marquee must enclose an entire context to select its container. Drag its heading to move the context and its contents. Both skin families follow inner nodes in every direction, including negative local positions: Standard fits a rectangle, and Atlas fits a polygon. Moving a selection preserves its spacing and attached notes; the context heading follows above its contents. Empty-canvas clicks and Escape clear selection; showing code or refreshing the model does not restore a cleared selection. **Add note** attaches only when exactly one model reference is selected.

Contexts always show their concepts and authored relationships. Earlier collapse preferences are ignored, and older collapsed canvas snapshots restore their full frame sizes while retaining child placements and attached notes.

Dragging a model object previews the space it needs: nearby siblings ease aside, then return to their original positions when you move past them. Each preview starts from the layout before the drag, so repeated passes do not accumulate displacement. Releasing keeps only the current preview's required space. Escape restores the entire drag, and Undo restores the committed movement in one step. Keyboard nudges resolve overlaps immediately.

Contact can propagate through a row, and expanding group boundaries move neighboring groups with their contents. Selected objects stay under the pointer; locked objects stay fixed. The preview works within each plane in 2D, Combined, and Planes, using the current skin's bounds. Freeform drawings and relationship labels do not participate; attached notes follow their targets. Positions save as ordinary canvas presentation.

Collision handling uses a spatial grid and computes at most one preview per animation frame, from the innermost affected group outward. Nested geometry is cached for that calculation, with affected ancestors invalidated after inner movement. Short easing stops when neighbors reach their targets; reduced-motion preferences disable easing. There is no idle simulation or momentum. Each sibling collision solve checks at most 20,000 candidates, including noncontacts and oversized groups; exhausted budgets, locked objects, or mutually selected objects can leave overlaps. Opening a canvas does not rearrange existing overlaps.

Freeform text uses a compact scale alongside the model: Small is 13.5 px beside 14 px model labels, with larger sizes available for emphasis. The shared tldraw theme keeps text measurement, editing, and exports consistent.

The toolbar uses Lexicon's shared icons and selection title; the footer shares its semantic legend. Routine save status appears in the footer. Right-click a model object for **Focus**. Cross-dimension radials connect Domain and Architecture neighbors and connect source targets or file cards back to their owners. Hover or focus a radial neighbor to read a temporary Reader card without changing selection or history. The card stays open while you move into it; leaving or pressing Escape dismisses it. Pin keeps it in the Reader. Clicking the radial still navigates to its dimension. Source links appear in the Reader card, not in the radials. Sources are not expanded inline on Domain or Architecture. **Back to overview** restores the preceding camera. Radial placement samples only routes that can overlap its candidate icons or names, and reuses local path samples across screen translations.

**Notes** lists and searches canvas notes and text, including the names of their attached objects. Select a result to locate it; its URL includes the shape ID. **Copy note link** copies that location. Open **Selection actions** with a note selected to attach it to a model object, detach it, or reattach it without changing its text.

Main model references cannot be renamed, deleted, rewired, or reparented by canvas gestures. Context ownership always comes from the model. Standard derives a padded rectangle from all inner model nodes and their labels; notes, selection, search, and source targets do not change its bounds. Atlas derives its territory during dragging and keyboard movement. Border preferences yield to complete node footprints and labels, so a coast never blocks a node. Duplicating or pasting a model card creates a labeled reference copy with an independent position. Missing model objects and relationships retain their references and attached notes for review; those missing references can be deleted.

In **Selection actions**, **Move to context** explicitly changes a concept's owner. **Add to model** previews a note as an annotation on a chosen object, with a kind and optional evidence qualification. Both actions use the existing model validator, revision checks, artifact-root rules, and Chat undo history. Built-in example models remain read-only. Canvas undo affects canvas edits; **Undo model edit** restores exact XML and refuses to overwrite a newer edit. Further semantic changes are available through Chat's incremental model-edit workflow.

Model refresh reconciles references by stable identity. New code links should have an `id` unique within their owner; preserve it when changing their target. Older links get deterministic target-and-role identities, so reordering or editing an explanation preserves attachments. Changing an unidentified link's target or role can leave a missing reference. Opening a model never adds IDs to XML. Old index-based canvas references and URLs migrate on read.

**Arrange** resets the model layout while retaining freeform content. Canvas Undo restores the previous layout and border preferences; Redo reapplies the arrangement. In Combined, all three planes are one undoable action. Attached notes follow their targets. **Fit model** frames the visible model; tldraw's navigation menu also fits all canvas content. Code shapes are created as their links are opened, and previously placed code references are retained.

## Atlas skins

The **2D skin** toggle group offers **Standard** model cards and rectangular context frames, **Atlas · Ink** for the pen-and-paper style, and **Atlas · Village** for illustrated terrain and buildings. Atlas is available in every 2D view; linked file and target cards keep their source styling. The skin is a browser preference and does not change shared canvas appearance choices or model XML. Switching skins preserves positions, selection, and camera. New workspaces start in Domain with the Standard skin; existing Map and Atlas preferences are retained. Switching between 2D and Planes preserves the 2D skin. Concepts anchor landmarks, and visible semantic relationships supply the road routes. Panning and zooming carry the map with the canvas.

Atlas generates a rounded contour around the context's current inner nodes and title, with room for both card and landmark appearances. It grows and shrinks during movement, and its actual coast drives selection and context-road endpoints. Select a context and choose **Edit border** to reveal native vertex handles and their faint dashed control outline; **Finish border editing** hides them. Editing stays active through model refresh while that context remains selected; changing the selection or leaving Atlas ends it. Each drag saves a local border preference. A sculpted bay yields when a node moves into it and returns when the node leaves. **Reshape to contents** clears those preferences. Border edits and reshaping support canvas undo. **Arrange** also resets border preferences when it lays out the model. Empty contexts retain a small title territory.

Terrain selects the physical boundary: Village has a stone rampart, Woodland a clustered treeline, Highlands an eroded escarpment, Wetland reed beds and channels, and Island a sandy shoreline. The generator samples coherent irregular reaches independently of contour tessellation and leaves model objects and road crossings clear. Only Village generates walls, varied towers and gate openings; isolated villages receive a main entrance where space permits. Natural boundaries retain crossing locations without artificial gatehouses. Both skins share this structure, but use different drawing vocabulary: Village depicts raised masonry and colored terrain, while Ink draws village ramparts in plan view and uses sparse contours, open crowns and hatching for natural edges. Ink never renders the Village fortress artwork. Village favors a transparent raster atlas for boundary trees, cliffs, reeds, shoreline rocks and towers. The engine overlaps upright sprites using stable variants and checks their complete footprints against model objects and roads. Continuous masonry retains vector geometry with a raster stone texture; gate openings remain geometric to follow the approach. Ink remains entirely vector. Viewing geometry and editable context contours stay unchanged.

Atlas generation filters roads with precomputed conservative bounds before exact clearance checks. Each canvas view caches districts against its own geometry and local roads, object obstacles and neighboring context bounds. Unchanged districts retain their identity, letting the ground and boundary renderers skip unrelated updates. Removed districts and roads leave the cache; model changes invalidate their keys. Wall faces, caps and full tower footprints share geometry helpers with road clearance; obstructing wall sections lower or disappear, and obstructing towers are omitted.

The rounded ground contour remains shared by selection, context-road docking, bridge crossings, and island scenery containment. Rounding becomes smaller near protected contents or tight edits; the stored edit controls remain independent of its sampled curve.

Automatic geometry is derived from current contents in both modes; only authored border preferences are saved in `canvas.json`. Preferences record local added and carved regions independently of generated vertex indices. Node moves do not rewrite those preferences, so undo, redo, and reload reproduce the same coastline without a separate border history. New concepts and longer labels enlarge the territory; moving or removing nodes lets it recede. Earlier saved polygons become preferences without moving their children. The context origin remains fixed, preserving children and attached notes. Local unions and differences use [polygon-clipping](https://github.com/mfogel/polygon-clipping).

Coast edits are anchored within the context. An edit in an abandoned area can become dormant until contents return; **Reshape to contents** forgets it. The territory remains a single outer polygon: holes are filled and cuts that split occupied areas receive a connecting strip. Edge variation uses direction rather than hull indices, and scenery keeps its stable local grid to limit distant changes during movement. Overlapping territories are allowed; moving a node over another context does not change its owner or silently rearrange the model.

Atlas roads have rounded bends, uneven ink banks, light wheel ruts, and small direction marks. They narrow into landmark entrances and skirt the labels below buildings. Their selectable surface follows the generated road, while landmarks and notes remain selectable where roads pass beneath them.

Node frames fit their contents: artwork and a name in Atlas, or the label in Standard. Long names wrap. Selection uses one outline around that visible frame. Appearance and skin changes preserve the node's shared center, and fitting a renamed node leaves its attached notes in place. Returning from the mobile reader refreshes the canvas viewport before drawing. A first visit without a personal camera fits the model once the canvas is visible; saved cameras retain their view.

Select a single model object to change its appearance:

| Selection | Choices |
| --- | --- |
| Context | Village, woodland, island, highlands, or wetland |
| Concept | By classification, house, hall, workshop, archive, tower, garden, or none |
| Relationship | Road, trail, or none |

By classification uses a hall for an aggregate, a workshop for a service, a tower for an event, a garden for a value, and a house otherwise. These are visual mnemonics; an island does not assert isolation, and a tower does not assert authority. Names, semantic icons, relationship labels, and code links continue to carry the model's meaning. Escape returns from an appearance control to the canvas. Canvas undo also undoes appearance changes.

Appearance choices are stored on the existing model-reference shapes in `canvas.json`. The generator uses stable model and object identities, with separate seeds for each patch of scenery, so adding an unrelated object does not redraw the whole village. Trees and fields leave room for concepts, relationship labels, notes, and visible paths. Island bridges appear where a relationship route crosses its boundary. Small scenery is omitted below 40% zoom. Search dims unmatched landmarks and roads.

Ink uses original SVG marks inspired by [Watabou's Village Generator](https://watabou.github.io/village.html): uneven groves with conifers, rounded crowns, low shrubs, open branches, and varied fields. Sparse ground hatching and a selected subset of contour-drawn mountains, hills, rocks, ponds, and springs give it variety while retaining a quiet pen-and-paper appearance. Each skin controls its own density and level of detail; they do not need to draw every feature one for one. Village uses an original transparent sprite sheet generated with GPT Image, composed inside the same SVG using `<image>` elements. The procedural generator still supplies numeric geometry: territories, road surfaces, landmark anchors, and scenery positions. Raster crops fit the existing landmark footprints; hit testing, labels, selection, and camera remain native canvas operations. Terrain and roads remain vectors, with organic meadow, dry-grass, earth, and shade patches plus sparse grass and pebble marks. A second classic-style sprite sheet supplies mountains, rocky hills, springs, ponds, groves, birches, shrubs, wildflowers, and boulders. Vegetation grows in uneven clusters with varied species and sizes. Large landscape features remain visible below 40% zoom; smaller growth and ground marks drop out. Highlands favors mountains and rocky vegetation; Wetland favors springs, ponds, and leafy growth. Landscape features occupy available space around a context, clear model objects and roads, and stay inside island coastlines. These are decorative terrain choices, not additional domain meanings. The sprite sheet is bundled and cached with the offline app shell; failed image loads fall back to Ink marks. Raster detail has a finite zoom resolution. See the [asset provenance and generation prompts](client/src/canvas/terrain/assets/README.md). Neither skin calls an external generator at runtime or bundles copied Travian artwork. Rendering does not move model objects or write to `model.xml`; native canvas gestures remain authoritative. Code mappings keep their existing appearance. Portable canvas files retain map choices, while selection PNG exports currently use the conventional model cards without the background map.

In Architecture, systems and containers become nested territories, components default to workshops, and people default to traveler markers. Ink and Village share the same geometry; travelers use an original vector illustration in both skins. **By element type** restores these landmark defaults. Territory and landmark appearance controls, road styling, border editing, notes, search, and code navigation work as they do in Domain. Parent territories fit the complete outlines of their children. These visual metaphors do not add domain membership or change the C4 types in the model. Planes continues to use its existing Standard presentation.

## Export and import

**File → Export canvas** creates a portable `.lexicon-canvas.json` with embedded media. **Restore canvas** validates its schema, model ID, records, and attachments before replacing the working canvas. It accepts the original prototype format and current version 2 files. **Undo restore** returns to the pre-import document. Imports can come from another path or machine with the same model ID.

**Selection actions → Export selection** downloads a PNG. Selecting a context includes its children and the relationships between them. Custom model cards and relationships have SVG export renderers, so they appear beside notes, drawings, and media.

Media uploads support PNG, JPEG, GIF, WebP, AVIF, MP4, and WebM, up to 25 MB each. The server checks content hashes and confines files to the artifact root. Assets are retained after shape deletion for undo, recovery, and Git history; automatic garbage collection is intentionally absent. A missing asset is reported rather than silently dropped. Shared canvas JSON is limited to 20 MB and 20,000 records; embedded export/import files are limited to 50 MB.

When no saved canvas or recovery snapshot exists, the first projection imports compatible earlier placements and camera from this browser. Context bounds fit migrated children while preserving their saved positions. The original saved viewing state is retained, and a saved canvas always takes precedence on later opens.

The original prototype's browser database is read once when the project has no companion file, using the pinned SDK's IndexedDB format. Local media is copied into the project, and the original database is retained. Export from the original browser if its media is no longer available. Lexicon exports require Lexicon's custom shapes and cannot be opened directly in an unmodified tldraw editor.

## Validation and rollout

The implementation has a few explicit boundaries:

| Responsibility | Files |
| --- | --- |
| Canvas UI, selection, and model actions | `client/src/canvas/CanvasPane.tsx`, `CanvasInspector.tsx` |
| Editor-owned model, mode, search, and border-editing presentation state | `presentation.ts`; shared by React rendering and native geometry |
| Shape rendering, model projection, and stable reference IDs | `shapes.tsx`, `projection.ts`, `references.ts` |
| Ink scenery, roads, SVG drawing, and appearance controls | `client/src/canvas/terrain/`; receives complete context geometry |
| Automatic context bounds and editable coast preferences | `contexts.ts`, `territory.ts`; native movement keeps model ownership |
| React boot state and editor save lifecycle | `useProjectCanvas.ts`, `persistence.ts` |
| Local API calls, portable files, and browser recovery | `api.ts`, `files.ts`, `recovery.ts` |
| Shared document capture and reference migration | `document.ts` |
| File format, limits, record schemas, and merge rules | `shared/canvas.ts`, `canvas-schema.ts`, `canvas-merge.ts` |
| Editor-independent geometry types and territory-region preconditions | `shared/canvas-geometry.ts`; enforced by the record schema |
| Project file storage and semantic command rules | `server/canvas.ts`, `server/canvas-command.ts` |

Each editor owns one persistence controller and disposes it on unmount. A saved revision and its merge base must stay paired; a draft with no prior save has a null base and requires review if a project file appears elsewhere. Projection calls `ready()` after applying a snapshot so generated references are reconciled before autosave. Canvas model commands use Chat's existing revision checks, file writer, and undo history.

`contexts.ts` derives boundaries from model children and authored preferences; the ink generator only decorates the supplied boundary, label, and origin. Saved edit regions allow empty additions or cuts, and open or closed rings. Missing, empty, or degenerate rings are rejected before a save or restore replaces the current document. Geometry and browser containment checks measure polygon difference area independently of the production containment predicate.

Keep the `lexicon-canvas-prototype.db` development registry filename and original browser database keys compatible with existing local data. The workshop launcher now uses `LEXICON_CANVAS_WORKSHOP`; the server still accepts its earlier `LEXICON_CANVAS_PROTOTYPE` name.

PLAYWRIGHT_CHANNEL=chrome bun run test:browser

Canvas browser checks build the client and run the normal `bun run start` server on isolated port 5395 with temporary projects. They open ordinary project URLs with Canvas as the default. The reader checks use port 5384 and an isolated registry. See `tests/canvas-storage.test.ts` for file, schema, concurrency, and media contracts, and `tests/canvas.e2e.ts` for browser interactions and recovery. API checks cover explicit canvas-to-model commands and exact undo. Routing lifecycle browser regressions cover nested frame endpoints and worker replies interrupted by camera gestures; the crossed-morph check samples primary-edge release animation. Persistence gesture tests pause asynchronous storage and conflict reads to check that automatic work cannot capture or replace an active drag. Radial obstacle tests compare culled and complete placement results.

They cover native gestures, navigation, code links, narrow screens, errors, persistence, recovery, model edits, and export.
